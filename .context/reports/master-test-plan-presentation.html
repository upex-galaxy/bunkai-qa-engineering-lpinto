CRÍTICO · RLS04 / 14
Aislamiento Tenant

Una política faltante = fuga silenciosa

RLS es el ÚNICO mecanismo de autorización. Cada tabla con `workspace_id` FK debe tener políticas correctas.

Qué se rompe comúnmente

• Nuevos endpoints PostgREST sin RLS
• SECURITY DEFINER helpers con recursión infinita
• Operaciones bulk PATCH que saltan policy checks
• SELECT con IDs crafted que evitan workspace filter

✓
Crear entidad en Workspace A → leer/actualizar/eliminar desde B → 403 o lista vacía
✓
PAT de Workspace A no lista recursos de Workspace B
✓
`current_workspace_id()` no retorna workspace_id incorrecto al cambiar de sesión

CRÍTICO · Dual-Path05 / 14
Paridad Cookie vs PAT

Dos caminos, una identidad

El Principal unificado (ADR-0001) colapsa cookie y bearer en una identidad. `mintUserJwt` crea un JWT por request y ejecuta el DB client AS el usuario bajo RLS normal.

RIESGO

Si falla

• JWT claims sin `workspace_id`
• Expiry del PAT JWT no coincide con token
• DB client usa service role en vez de user-scoped
• Workspace context no propagado

VERIFICAR

Qué probar

• Crear entidad como cookie → leer como PAT → resultado idéntico
• PAT workspace A → endpoint workspace B → 403
• `assertWorkspaceContext` bloquea cross-workspace admin

CRÍTICO · Runs06 / 14
Máquina de Estados — Run Execution

Tres granos, un invariante

`aborted` es SOLO run-grain. Un paso es `skipped`, NUNCA `aborted` (BK-317).

RUN GRAIN

runs.status

running → passed / failed / aborted

Terminal via finish (verdict) o abort (reason ≤500ch)

POSITION GRAIN

run_atcs.status

pending → passed / failed / blocked / skipped

Recomputado via trigger en cascada desde run_steps

STEP GRAIN

run_steps.status

pending → passed / failed / blocked / skipped

Single mark por step (`bunkai_mark_run_step`)

Cascada de triggers

Step mark → trigger recomputa run_atcs → finish/abort → activity + notifications. Un trigger fallido = estado inconsistente en reportes.

CRÍTICO · Auth07 / 14
Signup Verificación-Primero (BK-166)

Sin confirmación = sin credenciales

FLUJO

Qué debe pasar

1. Signup → 202 `pending_confirmation` (NO session, NO PAT)
2. Email OTP (6–8 dígitos)
3. Confirm → 200 con session + PAT atómicamente
4. Duplicate email → 409 sin echo de existencia

EDGE CASES

Qué probar

• OTP wrong → 401 uniforme (sin distinguir "no existe" de "código mal")
• OTP expirado → rechazo correcto
• Resend invalida OTP anterior
• Password: signup min(8), signin min(6) legacy

Adelante-solo y scopes enforced

BUGS

Vida — Adelante-Solo

open → in_progress → resolved → closed

Trigger + RPC double layer. Salto = 45310, retroceso = 45311. Asignee debe ser member ≥ member (45312/45313).

SCOPES

Enforcement via `requires:`

atc:read · atc:write · run:execute · workspace:admin

`workspace:admin` aceptado al mint pero rechazado en runtime (ADR-0005). Cookie = todas caps.

Double layer debe concordar

Trigger DB y RPC de bugs validan la misma restricción. Si no concuerdan, transiciones inválidas pasan silenciosamente.

ALTO · ATC + Cobertura09 / 14
ATC Save, Cobertura, Idempotency

Tres pilares functionales

ATC SAVE

RPC Atómico

Header + steps + assertions + AC bindings en una transacción. `X-If-Match` = optimistic lock (409 on conflict). Propagación a tests encadenados (0035).

COBERTURA

Invariante sum/sum

`sum(ac_bound)/sum(ac_total)` — NUNCA media de porcentajes. Home y API comparten `lib/home/coverage.ts`. Nunca deben discrepar.

IDEMPOTENCY

Replay Store Funcional

Runs/tests/atcs/imports. HTTP key + ventaja 24h `start_token` en runs. Misma key + mismo body = stored result.
