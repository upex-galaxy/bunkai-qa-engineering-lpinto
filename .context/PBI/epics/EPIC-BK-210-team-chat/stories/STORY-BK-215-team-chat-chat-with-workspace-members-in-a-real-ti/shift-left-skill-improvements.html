Objetivo: Estandarizar la estructura de salida del shift-left testing para garantizar consistencia entre sesiones y facilitar la sincronización con Jira.
Archivo Tipo de Cambio Descripción

⚖️ Comparación: Sin Cambios vs Con Cambios

ANTES Sin Prompt Template

  • Estructura variable según la sesión
  • Cada QA genera contenido diferente
  • Posible mezcla de Description y ATP DRAFT
  • Sin reglas de formato para Gherkin
  • Requiere knowledge transfer manual
  • Hardcodear estructura en cada sesión

DESPUÉS Con Prompt Template

  • Estructura fija de 15 fases
  • Salida idéntica en cada sesión
  • Separación clara: Description vs ATP
  • Reglas de formato documentadas
  • Template reutilizable inmediatamente
  • Carga automática desde la skill

📝 Estructura del Prompt Template

FASE 1-4 Análisis Crítico

Contexto Business + Técnico + Hechos confirmados + Complejidad del Story + Herencia del Epic

FASE 5-7 Calidad del Story

ACs Refinados (Gherkin) + Hallazgos Críticos + Ambigüedades

FASE 8-12 Gaps y Preguntas

Gaps (info faltante) + Business Rules + Preguntas PO/Dev/Diseño + Respuestas Propuestas + Mejoras

FASE 13-14 ATP DRAFT

Coverage Estimate + Test Outlines + Traceability Map + Test Data/Environment + Entry/Exit Criteria + Risk-Based Prioritization + Open Items + Risks & mitigation

FASE 15 Sincronización Jira

Separación de contenido (Description vs ATP DRAFT) + Comandos de sincronización + Reglas de formato

ANTES Sin Template

## Acceptance Criteria

1. Users can send messages in real-time
2. Message history is persisted
3. Viewers can read but not send

❌ Sin formato Gherkin
❌ Sin escenarios 1:N

❌ Sin edge cases

DESPUÉS Con Template

```gherkin
AC1: Real-time message delivery

  Scenario 1.1 (Critical): Two members receive message
    Given Two members have the channel open
    When One member sends a message
    Then Message appears for both without refresh

  Scenario 1.2 (High): Cross-workspace isolation
    Given User belongs to a different workspace
    When Foreign message is sent
    Then Foreign messages do not appear
```

✅ Formato Gherkin con syntax highlighting
✅ Escenarios 1:N (1.1, 1.2, 1.3...)
✅ Prioridades (Critical, High, Medium)
✅ Edge cases (Scenario E1, E2...)

DESPUÉS Separado por propósito

Description (WHAT):
  - User Story
  - Context (Business + Technical)
  - Critical Analysis
  - Story Complexity
  - Epic-level Inheritance
  - Refined ACs (gherkin code block)
  - Critical Findings
  - Ambiguities + Gaps
  - Questions (PO/Dev/Design)
  - Next Steps

ATP DRAFT (HOW):
  - Coverage Estimate
  - Test Outlines (Positive, Negative, etc.)
  - Traceability Map
  - Test Data/Environment Requirements
  - Entry/Exit Criteria
  - Risk-Based Prioritization
  - Open Items
  - Risks & mitigation

Reglas de Formato (agregadas)

**Formatting rules (MANDATORY — from prompt template):**

- **Code block for ACs**: Use ` ```gherkin ` for syntax highlighting
- **No colons in Gherkin**: `Given` (no `Given:`)
- **Content separation**: Description = WHAT, ATP DRAFT = HOW
- **Tables with headers**: Always include column headers
- **Backup before modifying**: Save current Jira JSON before PUT
- **Verify after PUT**: Confirm HTTP 204 and read back content
