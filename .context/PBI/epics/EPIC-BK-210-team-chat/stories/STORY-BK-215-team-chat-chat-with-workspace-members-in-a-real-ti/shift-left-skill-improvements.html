Reglas de Formato (agregadas)

**Formatting rules (MANDATORY — from prompt template):**

- **Code block for ACs**: Use ` ```gherkin ` for syntax highlighting
- **No colons in Gherkin**: `Given` (no `Given:`)
- **Content separation**: Description = WHAT, ATP DRAFT = HOW
- **Tables with headers**: Always include column headers
- **Backup before modifying**: Save current Jira JSON before PUT
- **Verify after PUT**: Confirm HTTP 204 and read back content

Compact Rule — NFR Procedure (agregada)

- **NFR gaps → NEVER formal ACs** (performance/accessibility/
  scalability silent in the Story): propose NFRs as outlines (NFR1-NFR4)
  + edge scenarios (E4-E7) marked `NEEDS PO/DEV CONFIRMATION`
  + blocking Technical Questions. PO/Dev confirmation upgrades them
  to contract → failures become Defect; before confirmation they are
  Improvement. Full procedure: `references/nfr-proposal-procedure.md`.

⚡ Procedimiento NFR — Gaps No Funcionales

Problema resuelto: Cuando el Story no menciona NFRs (performance, accesibilidad, escalabilidad), la skill antes no hacía nada o inventaba ACs formales. Ahora propone outlines + escenarios marcados NEEDS PO/DEV CONFIRMATION — la confirmación los convierte en contrato (fallas = Defect); sin confirmar, son Improvement.
Dimensión Detección Ejemplo de probe
Performance Claims de volumen/latencia sin números ("real time", "large history") Latencia de delivery bajo carga concurrente; tiempo de carga de historial 10,000+ mensajes
Accessibility Sin target WCAG; interacciones solo-teclado implícitas Navegación por teclado (focus visible); screen reader (live regions); presence no solo-color
Scalability Concurrencia mencionada sin límites N miembros enviando simultáneamente

Ejemplo aplicado (BK-215): escenarios propuestos E4-E7 en Description

```gherkin
Scenario E4 (High): Should meet delivery latency SLA under concurrent load (NFR - Performance)
    Given 10 members have the general channel open and send messages simultaneously.
    When All messages are delivered to all members.
    Then Message delivery latency stays within the agreed SLA (scenario 1.1: under 2 seconds). NEEDS PO/DEV CONFIRMATION.
```

Consistencia numérica (MANDATORY) — los 6 lugares deben coincidir

1. Coverage Estimate: fila `Non-Functional | 4`
2. Coverage Total: bump 26 -> 30
3. Traceability Map: filas E4-E7 -> NFR1-NFR4 (needs PO confirmation)
4. Exit Criteria: "[ ] NFR verification executed"
5. Risk-Based Prioritization: NFR1-NFR4 en P1 + rationale
6. Risks: riesgo "NFRs undefined" -> NFR1-NFR4, Tech Questions #10-#11
// "All N outlines executed" en Exit Criteria DEBE igualar el Total

🌐 Phase 4 — Comparación con Mejores Prácticas del Mercado

Problema resuelto: El proceso quedaba estático. Ahora, tras sincronizar Description + ATP DRAFT, la skill pregunta al usuario si quiere una búsqueda exhaustiva en internet sobre qué debería tener una user story post-shift-left, y compara los resultados con la story refinada — manteniendo el proceso actualizado con las mejores prácticas del mercado.
  • Opt-in gate (MANDATORY) — nunca se ejecuta automáticamente: siempre pregunta tras el handoff
  • Investigación exhaustiva — [WEB_SEARCH_TOOL] (Tavily, advanced): canon Agile/ISTQB + queries específicas del dominio
  • Tabla de gaps — veredicto ✅/⚠️/❌ por dimensión + fuente citada por fila
  • Presentar opciones y ESPERAR — nunca modificar Jira sin aprobación explícita (ej. A: ACs formales · B: outlines + NEEDS PO/DEV CONFIRMATION (default) · C: dejar como está)
  • Bookkeeping — investigación persistida en .session/.../market-comparison.md + entrada en progress.md
