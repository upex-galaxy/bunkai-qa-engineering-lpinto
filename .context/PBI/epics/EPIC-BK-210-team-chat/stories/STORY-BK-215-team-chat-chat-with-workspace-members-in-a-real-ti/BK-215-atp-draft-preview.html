2 Test Outlines (Names Only)

Positive (7)

Positive P1: Should deliver a new message to all channel members in real time
Pre: two members have channel open. Expected: new message appears for both without refresh.
Positive P2: Should display sender name and timestamp on each message
Pre: message exists. Expected: sender display name + formatted timestamp.
Positive P3: Should load full history when user opens the channel
Pre: channel has 20+ messages. Expected: all messages in chronological order.
Positive P4: Should load older messages on scroll-up
Pre: more messages than fit on screen. Expected: older messages load progressively.
Positive P5: Should display all workspace members with roles in roster
Pre: workspace has 3 members with different roles. Expected: roster shows all with role badges.
Positive P6: Should allow viewers to read full message history
Pre: viewer opens channel. Expected: full history readable.
Positive P7: Should show missed messages after reconnection
Pre: connection drops while messages arrive. Expected: missed messages in correct order on reconnect.

Negative (4)

Negative N1: Should not deliver messages to non-members of the workspace
Pre: user belongs to different workspace. Expected: foreign messages do not appear.
Negative N2: Should prevent viewers from sending messages
Pre: viewer attempts to send. Expected: send rejected at server level.
Negative N3: Should reject empty or whitespace-only messages
Pre: user types only spaces. Expected: not sent, error shown.
Negative N4: Should not show messages from other workspaces
Pre: user has access to multiple workspaces. Expected: channel shows only current workspace messages.

Boundary (5)

Boundary B1: Should accept message at exactly 1 character
Pre: user types single character. Expected: sent successfully.
Boundary B2: Should accept message at exactly 4000 characters
Pre: user types 4000 chars. Expected: sent successfully.
Boundary B3: Should reject message at 4001 characters
Pre: user types 4001 chars. Expected: rejected with error.
Boundary B4: Should handle leading/trailing whitespace correctly
Pre: user types " Hello ". Expected: trimmed and sent as "Hello".
Boundary B5: Should handle disconnection window boundary
Pre: connection drops for exactly the catch-up window. Expected: messages load or refresh prompted.

Integration (4)

Integration I1: Should enforce channel access through workspace membership
Pre: user is/is not a workspace member. Expected: access granted/denied based on membership.
Integration I2: Should render chat panel within App Shell
Pre: user opens panel. Expected: right-side dock consistent with BK-147 patterns.
Integration I3: Should persist messages to the database
Pre: message sent. Expected: stored in messages table with correct foreign keys.
Integration I4: Should subscribe to Realtime for message delivery
Pre: channel open. Expected: Realtime subscription active, receives new messages.

Security-RBAC (3)

Sec-RBAC S1: Should enforce viewer read-only at the API level
Pre: viewer sends via API. Expected: 403 Forbidden returned.
Sec-RBAC S2: Should isolate workspace channels from each other
Pre: user accesses channels from different workspaces. Expected: no cross-workspace leakage.
Sec-RBAC S3: Should enforce role-based access on channel operations
Pre: user with different roles attempts operations. Expected: permitted/denied per RBAC.

State-Transition (3)

State ST1: Should handle connected→disconnected transition
Pre: user connected then loses connection. Expected: UI reflects disconnection, reconnects automatically.
State ST2: Should handle member→viewer role transition
Pre: member's role changes to viewer. Expected: composer disables in real-time.
State ST3: Should handle empty→populated channel transition
Pre: channel has 0 messages, then message sent. Expected: empty state disappears, message appears.
